# grpc and protobuf reference code

`grpc/` and the root `proto_temp.go` are **learning material**, not part of the
gnet library. They exist so the "pb protocol over gnet" TODO has a working
starting point.

## What is here

| Path | Package | What it does |
|---|---|---|
| `grpc/grpc_temp_server.go` | `main` | grpc server on `:50051` with explicit keepalive policies, plus an in-process client in a goroutine |
| `grpc/grpc_temp_client.go` | `main` | empty file (`package main` only) |
| `grpc/protobuf/hello.proto`, `temp.proto` | — | `Greeter`/`HelloRequest`/`HelloReply`, and a `Person` message |
| `grpc/protobuf/*.pb.go` | `protobuf` | generated code, checked in |
| `proto_temp.go` | `main` | marshals/unmarshals a `Person` with `github.com/golang/protobuf` |

Run them with `go run ./grpc` and `go run .`.

## Why `grpc_temp_client.go` is empty

It is a leftover from when the client was a separate `main` file. Two `main`s
in one directory do not compile, so the client was folded into
`grpc_temp_server.go` (`func clientTest()`), and the file was truncated to just
the package clause to keep the name pair visible. `go build ./...` is happy
because a file with only `package main` is a valid (empty) package member.

Do not re-expand it into a second `main`. If a standalone client is needed,
put it in its own directory (`grpc/client/`), not alongside the server.

## Generated code

`protobuf/hello.pb.go` and `temp.pb.go` were generated by an old
`protoc-gen-go` (`github.com/golang/protobuf v1.3.2`, pre-`google.golang.org/protobuf`).
Consequences to know before touching them:

- They register types via the legacy `proto.RegisterType` global registry, so
  they must be regenerated **together** with `hello.proto`/`temp.proto` — editing
  a `.pb.go` by hand or upgrading only one file breaks the registry.
- The generated files also import `golang.org/x/net/context`, which is what
  pulls `x/net` into `go.mod` besides `tcp_fixed_head`/`websocket`.
- `google.golang.org/grpc v1.25.1` is old enough that
  `grpc.WithInsecure()` is the correct dial option (the newer
  `insecure.NewCredentials()` does not exist in this version). An upgrade of
  grpc means regenerating the protobufs and rewriting the client dial — treat
  it as a separate change, not a drive-by `go get`.

## Keepalive settings as documentation

`grpc_temp_server.go` sets an explicit `EnforcementPolicy` and
`ServerParameters`:

| Setting | Value | Meaning |
|---|---|---|
| `MinTime` | 5s | reject client pings more often than this |
| `PermitWithoutStream` | true | allow pings with no active RPC |
| `MaxConnectionIdle` | 15s | send GOAWAY if idle |
| `MaxConnectionAge` | 30s | force reconnection after 30s |
| `MaxConnectionAgeGrace` | 5s | time for in-flight RPCs before hard close |
| `Time` / `Timeout` | 5s / 1s | server-side ping cadence and ack wait |

The demo's point is that `SayHello` sleeps 5 seconds while the server allows a
30-second connection age and a 15-second idle timeout — so a client ping every
10 seconds (its `ClientParameters.Time`) keeps the connection alive across
requests, and `getGoroutineID()` shows whether a call is served on a new
goroutine. Read it as a keepalive example, not as a production configuration.

## The "pb over gnet" TODO

`README.md` lists `pb协议` as a TODO, and `commonutil.CodecEmpty` is the
scaffold for it. If you implement it:

- the protobuf here is only a message definition; a wire protocol still needs a
  length-delimited framing (protobuf itself is not self-delimiting), which is
  exactly what `tcp_fixed_head` already demonstrates;
- follow the `tcp_fixed_head` package shape (own package, `config.go` with the
  frame constants, streaming decode in `OnTraffic`, ants offload);
- do not wire `CodecEmpty` into `gnet.Run` options speculatively — it is not
  used and gnet v2's option list does not include a codec hook in this version.
