# grpc

`grpc/` is a reusable wrapper around `google.golang.org/grpc`. It is **not**
gnet-based, on purpose: gRPC already owns HTTP/2 framing, multiplexing, flow
control, and stream lifecycle. Re-implementing that on a raw reactor would lose
semantics, not simplify the server. The wrapper adds only what gRPC leaves to
the caller: listening, connection counting, lifecycle logging, and signal-driven
graceful shutdown.

The protobuf scratch demo (`proto_temp.go`) and the generated protobufs still
serve as the "pb over gnet" TODO's message definitions; they are unrelated to
this wrapper.

## What is here

| Path | Package | What it does |
|---|---|---|
| `grpc/server.go` | `grpc` | `Server`, `Run`, `Stop`, `GracefulStop`, `LocalAddr`, `GetConnNum`, signal handling |
| `grpc/server_factory.go` | `grpc` | `NewServer`: options first, then defaults (`Addr`, ctx) |
| `grpc/option.go` | `grpc` | `ServerOption` + `With*` constructors |
| `grpc/handler.go` | `grpc` | `ServiceRegistrar`, the registration extension point |
| `grpc/stats.go` | `grpc` | connection counting `stats.Handler` wrapper |
| `grpc/constants.go`, `grpc/exceptions.go` | `grpc` | `DefaultAddr` and sentinel errors |
| `grpc/protobuf/hello.proto`, `temp.proto` | — | `Greeter`/`HelloRequest`/`HelloReply`, and a `Person` message |
| `grpc/protobuf/*.pb.go` | `protobuf` | generated code, checked in |
| `examples/grpc/main.go` | `main` | server + in-process keepalive client; exits on its own |
| `proto_temp.go` | `main` | protobuf marshal/unmarshal scratch demo |

Run the example with `go run ./examples/grpc`; the scratch demo with `go run .`.

## API shape

```go
server := grpc.NewServer(
    grpc.WithAddr("127.0.0.1:50051"),
    grpc.WithServiceRegistrar(func(s *grpcgo.Server) {
        protobuf.RegisterGreeterServer(s, &helloServer{})
    }),
)

if err := server.Run(); err != nil { // blocks until Serve returns
    log.Fatal(err)
}
```

- `NewServer` does wiring only: no listening, no goroutines. Options are applied
  in order and defaults are filled afterwards, matching `tcp_fixed_head`.
- There is no `ServerHandler` func type. gRPC is service/method based, and the
  generated `RegisterXxxServer` functions already have the right shape, so the
  extension point is `ServiceRegistrar`. Multiple registrars run in order.
- `WithGrpcOptions` passes through raw `grpc.ServerOption` values (TLS,
  interceptors, ...). The wrapper appends its own `StatsHandler` last; use
  `WithStatsHandler` for a custom handler so connection counting still works.
- `Run` starts a signal goroutine and logs through `commonutil.GetLogger()`.
  A nil `Server` or one built without `NewServer` returns `ErrNotConstructed`.
  `Run` may be called once; a failed `net.Listen` clears the started flag so a
  corrected address can be retried. `Stop` returns `ErrNotRunning` after exit.

## Connection counting

gRPC has no gnet `OnOpen`/`OnClose`; the equivalent events are
`stats.ConnBegin` / `stats.ConnEnd`. `connStatsHandler` wraps an optional
caller-supplied handler, increments/decrements `ConnNum` with `atomic.AddInt64`,
and forwards every callback. Read it through `GetConnNum()`; reading the field
directly races with the stats callbacks.

`HandleConn` receives a context from the earlier `TagConn` call. The wrapper
must attach its own remote-address tag before delegating to `next.TagConn`,
otherwise the address lookup falls back to `unknown`.

## Shutdown

`Run` selects on the OS signal channel and `doneCh`. `Stop` and
`GracefulStop` close `doneCh` before calling into gRPC, so the signal goroutine
does not stay registered in `signal.Notify` after an in-process stop. OS signals
call `GracefulStop`; there is no forced-stop timeout — an RPC that never returns
will keep shutdown waiting, so handlers should respect their context.

`Serve` returns `grpc.ErrServerStopped` after a stop; `Run` normalizes that to a
nil error and logs `[server] grpc server shutdown`.

## Generated code

`protobuf/hello.pb.go` and `temp.pb.go` were generated by an old
`protoc-gen-go` (`github.com/golang/protobuf v1.3.2`, pre-`google.golang.org/protobuf`).
Consequences to know before touching them:

- They register types via the legacy `proto.RegisterType` global registry, so
  they must be regenerated **together** with `hello.proto`/`temp.proto` — editing
  a `.pb.go` by hand or upgrading only one file breaks the registry.
- The generated files also import `golang.org/x/net/context`, which is what
  pulls `x/net` into `go.mod` besides `tcp_fixed_head`/`websocket`.
- `google.golang.org/grpc v1.25.1` is old enough that
  `grpc.WithInsecure()` is the correct dial option (the newer
  `insecure.NewCredentials()` does not exist in this version). An upgrade of
  grpc means regenerating the protobufs and rewriting the client dial — treat
  it as a separate change, not a drive-by `go get`.

## Keepalive settings in the example

`examples/grpc/main.go` sets an explicit `EnforcementPolicy` and
`ServerParameters`:

| Setting | Value | Meaning |
|---|---|---|
| `MinTime` | 5s | reject client pings more often than this |
| `PermitWithoutStream` | true | allow pings with no active RPC |
| `MaxConnectionIdle` | 15s | send GOAWAY if idle |
| `MaxConnectionAge` | 30s | force reconnection after 30s |
| `MaxConnectionAgeGrace` | 5s | time for in-flight RPCs before hard close |
| `Time` / `Timeout` | 5s / 1s | server-side ping cadence and ack wait |

`SayHello` defaults to a 5-second delay (`--greet-delay`). With a 30-second
connection age and 15-second idle timeout, the client's 10-second
`ClientParameters.Time` keeps the connection alive across requests, and
`getGoroutineID()` shows whether a call is served on a new goroutine. Read it as
a keepalive example, not as a production configuration. Pass
`--greet-delay 0s` for a fast smoke test.

## The "pb over gnet" TODO

`README.md` lists a gnet-based protobuf protocol as a TODO, and
`commonutil.CodecEmpty` is the scaffold for it. If you implement it:

- the protobuf here is only a message definition; a wire protocol still needs a
  length-delimited framing (protobuf itself is not self-delimiting), which is
  exactly what `tcp_fixed_head` already demonstrates;
- follow the `tcp_fixed_head` package shape (own package, `constants.go` with
  the frame constants, `exceptions.go` with sentinels, `option.go` for the
  constructor knobs, streaming decode in `OnTraffic`, ants offload);
- do not wire `CodecEmpty` into `gnet.Run` options speculatively — it is not
  used and gnet v2's option list does not include a codec hook in this version.
